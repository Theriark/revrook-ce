# Changelog

All notable changes to revrook CE are recorded in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project will follow [Semantic Versioning](https://semver.org/) once it has a release.

No version has been released: there is no stable tag, no stable GitHub release and no released image (the only image is the one built for each `development` commit and deployed to the Development environment). The annotated tags `v27.0.0-rc.1`, `v27.0.0-rc.2` and `v27.0.0-rc.3` mark earlier release candidates of Development, made by the `prepare-rc` job; they are not releases. Everything below is under Unreleased and describes the release candidate that the Development environment runs. The version in `pyproject.toml` is `27.0.0.dev0`, the development line of the v27 candidates, until a release is authorised ([docs/release-candidate.md](docs/release-candidate.md)).

## [Unreleased]

### Added

- A **finding** of the quarterly review prints the **usual next step** of its control when no recommendation was written for it: one general sentence for each of the 51 controls (`app/reports/advice.py`). What the technician recommends takes its place, and a control that passes on evidence grown old asks for a fresh export instead.
- A **logo of your business** on the cover of every report: upload a PNG, JPEG or WebP file (up to 200 KB) in Settings; it travels inside the report file. A **finding** now says what the check found when the report was made (for reports made from now on), and the cover prints the name you chose on the Account page as **Prepared by**. The kinds of evidence in a report are named in plain words ("Microsoft 365 export", "Backup jobs export") ([docs/reports.md](docs/reports.md)).
- On the **clients list** a sort, a search, a band or a page of the list moves the rows that stay, as on the checklist. The control drawer arrives on the arrival curve. Signed out, the words of the panel stand in the middle of it.
- The **overview of a client** fills its last row: the recent changes stand beside the domains, under the freshness line, instead of leaving half the row empty; the status bars grow from their left end when the page opens.
- On the **checklist**, narrowing, searching or sorting moves the rows: one that stays slides to its new place, one that leaves fades out, one that comes fades in. The name of the client and the tabs stay where they are from one page of a client to the next. The name of a control is text that takes the link colour when pointed at.
- The interface is set in **Inter**, served by the installation itself (`app/static/vendor/inter`, SIL Open Font License 1.1, accepted for font files only), so a page looks the same on every machine; tables draw their figures at one width, and a page title is 28 px at every width.
- **Motion** where it says something: a page change cross-fades the page column while the rail and the top bar stay, the score arc of Home and of a client draws to its value once, and the stat cards and the needs-attention rows arrive one after the other. In a needs-attention list the name of a control is text that takes the link colour when pointed at. All of it is off under `prefers-reduced-motion` ([design system](docs/design-system.md), Motion).
- Home's client street opens a **company card** beside the chosen office (score and band, its three most urgent controls, its exports to refresh, and Open client, Checklist and Evidence), docked under the stage on a phone ([guide 8](docs/guides/08-scenes-rail-and-explorer.md#the-company-card)).
- The **Evidence Explorer** is back in the rail (Evidence, after Evidence integrity) and opens on the **companies ring**: every active client as an office on an inner ring, all 51 controls on an outer ring by domain in the worst status any client has, and a link from every client to every control in the status of that pair. Filter buttons show or hide each status (not protected and needs attention at first); choosing an office opens the company card of Home, choosing a tile a card that lists every client with its status for that control, each opening in the control drawer. Companies and Controls tables under the scene carry the same counts. `?client_id=N`, the link of a client's evidence page, still opens that client's evidence wall; Home's street keeps the company card and no longer has a Ring view ([guide 8](docs/guides/08-scenes-rail-and-explorer.md#the-evidence-explorer)).
- **Import evidence** (`/imports`, in the rail): drop every export of a client at once, up to 20 files and 20 MB in all. Each file is recognised by its columns or its Microsoft Graph fields (an empty Graph answer by its `@odata.context`), including a vendor export with a saved column mapping of the profile editor, and stored on its own, so a refused file stops none of the others. The five Microsoft sources, which had no page before, are imported here ([docs/importers.md](docs/importers.md#the-import-page)).
- The public DNS check runs from the evidence page of a client, once or every Monday (a `dns-check` schedule of the worker), instead of only through the API.
- `app/static/scripts/export-m365.ps1`, offered for download on Import evidence: one read-only PowerShell run writes the six Microsoft 365 files (Entra registration, Secure Score, Intune devices, Conditional Access, directory roles and the Exchange Online settings CSV) ready to drop on the page.
- `app/static/scripts/export-aws.sh`: one read-only AWS CLI run writes an AWS account's inbound security group rules, running EC2 instances (with their disk encryption) and AWS Backup jobs as the `network-export`, `device-inventory` and `backup-export` CSV files Import evidence already reads ([guide 12](docs/guides/12-cloud-exports.md)).
- `app/static/scripts/export-gcp.sh`: one read-only Google Cloud CLI run writes the ingress VPC firewall rules, running VMs and disk snapshots of a client's projects in the same three CSV formats; a project without the Compute Engine API is skipped, never enabled ([guide 12](docs/guides/12-cloud-exports.md#google-cloud-export-gcpsh)).
- `app/static/scripts/export-cloudflare.sh`: one read-only Cloudflare API run (a token with Tunnel Read and Access Apps and Policies Read) writes every public tunnel hostname that no Access application guards as a `network-export` rule from any source to the port of its service (SSH 22, RDP 3389, SMB 445, TCP its port, web 443). The AWS backup file gains the `encrypted` column (empty), so the cloud files of each kind have the same columns ([guide 12](docs/guides/12-cloud-exports.md#cloudflare-export-cloudflaresh)).
- Device, backup and network exports of **several tools** count together: the three sources take an optional `tool` column (the three cloud scripts write `aws`, `gcp` or `cloudflare`), and the checks read the newest file of each tool of a client as one set of rows, measured from the newest capture, instead of only the newest file of the source. A file without a tool counts as one more tool, so importing a cloud export no longer pushes out the office firewall's file; a tool's file stops counting once it is more than 35 days older than the newest file of its kind ([importers](docs/importers.md#several-tools-of-one-source-the-tool-column), [guide 12](docs/guides/12-cloud-exports.md#import-the-files)).
- Every CSV source takes an optional `exported_at` column: its newest value is the file's capture time, so a script dates its own evidence, and a new export of an unchanged account is imported again instead of refused as a duplicate (the same bytes twice). The AWS, Google Cloud and Cloudflare scripts and the Exchange CSV of `export-m365.ps1` write it on every line; the leavers column `exported` is read as it ([importers](docs/importers.md#when-the-file-was-exported-the-exported_at-column)).
- The evidence page and the expiry reminders follow the tools of a device, backup or network source: its Sources row names the tools and is as old as the oldest file that counts (so a stale firewall export is not hidden by a fresh cloud one), and the newest file of each tool is reminded about on its own.
- PC-DEV-03 (no operating system past vendor support) can now be decided: `data/lifecycle.yaml` ships the vendors' end-of-support dates of Windows client and server builds and Ubuntu LTS (with their sources); a build that is two products (Windows 11 24H2 and Windows Server 2025) is told apart by the device's form factor ([controls](docs/controls.md)).
- `export-unifi.sh`, `export-checkmk.sh` and `export-xo.sh`: read-only exports of a UniFi console (gateway firmware date from Ubiquiti's public list, management open to the internet, syslog, port forwards and inbound allow policies without ICMP, which opens no port, Wi-Fi security, guest and isolation), a Checkmk site (agent hosts with their operating system and version, server or workstation, last contact, patch state when monitored) and Xen Orchestra (one line per VM of each scheduled backup job: newest result and success, schedule, retention, encryption, on or off site), as the `network-export`, `device-inventory` and `backup-export` files Import evidence reads. The jq scripts drop the CR that jq writes on Windows ([guide 12](docs/guides/12-cloud-exports.md#the-office-unifi-checkmk-and-xen-orchestra)).
- The System page shows the commit the image was built from (`REVROOK_REVISION`, set by the image build) beside the version.
- Documentation of the import page, the Microsoft 365 export script and the public DNS check: [guide 3](docs/guides/03-import-evidence.md) is rewritten around Import evidence (the three steps, the result table, the profile editor for an export with other column names), [guide 10](docs/guides/10-microsoft-365-export.md) walks through `export-m365.ps1` and the six files it writes, and [guide 11](docs/guides/11-public-dns-check.md) runs the DNS check from the evidence page, once or every Monday; guides 2, 4, 6, 7 and 8 describe the scenes that start hidden, the strictest-control age of the evidence pages, the notes the review prints, the build commit on the System page and the marked test accounts. Every picture of the set was captured again on 2026-11-11 from the Development site running commit `99aaf21b26a93a54b6db1aa5534e602c6e2e8541` (image `sha256:6bd4e84cbbabccfd8b96ad5f44e9ed714262412bb81cceb61fdedb9c75967e6c`), with six new pictures of the import page and the DNS check; the capture manifest (`docs/images/MANIFEST.json`, schema 4) and [docs/images/README.md](docs/images/README.md) record the set, and [docs/release-notes.md](docs/release-notes.md) the candidate and its limits.
